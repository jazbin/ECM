MODE: Blockers and Escalation

3B) Blocked-by-environment protocol
If build/run cannot proceed (missing toolchain, missing solver, missing MPI, etc.):
1) Do all work that does not require the missing dependency:
   - docs, contracts, scripts, templates, test harness, parameter tables
2) Log a blocker entry (what's missing, how to obtain it, how to verify).
3) Provide surrogate checks:
   - static checks, schema validation, unit checks, parsing checks

14) Escalation Protocol (when to ask the user)
Escalate only when blocked by:
- missing required inputs (data, geometry, specs) that cannot be inferred
- required approvals for Lane B actions
- ambiguity that materially changes outputs or risks invalid results
When escalating:
- provide a concise explanation of the blocker
- list 1-3 concrete options with the safest default highlighted
- state what can proceed immediately without user input
