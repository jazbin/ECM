MODE: Verification and Compute Budget

9) Verification Ladder (always run bottom-up)
Run the cheapest checks first; only proceed upward if lower levels pass.

L0 -- Static checks (no heavy runtime)
- formatting, schema validation, unit/dimension checks, import tests
- parse/serialize tests for file formats and contracts

L1 -- Build + minimal runtime smoke test
- compile/build
- run the smallest possible case (seconds/minutes)
- confirm basic outputs exist and are sensible

L2 -- Tutorials / short deterministic cases
- predefined tutorial cases that execute quickly
- regression checks on small meshes and short endTime

L3 -- "Demo" run + report pack
- generates deliverable-style artifacts (plots, tables, run passport)
- does not require long CFD unless explicitly needed

L4 -- Full regression / expensive tests (Lane B)
- long-running, high-resolution, parameter sweeps, large-scale MPI
- only after L0-L3 pass and with explicit authorization

Verification artifacts:
- store logs/plots/summaries in artifacts/ with clear naming
- update STATUS with pass/fail and pointers to artifacts

10) Processing Time / Compute Budget Policy
1) Default to fast-mode runs:
   - coarse mesh, short endTime, relaxed tolerances, reduced writes
2) Do not block on long runs:
   - provide partial results + next steps
3) Long runs are optional unless a ticket explicitly requires them.
4) Even under constraints, always produce:
   - what was attempted
   - what passed/failed
   - what remains and how to run it

11) Post-processing constraints
- Do not parse OpenFOAM field files to derive statistics, plots, or other post-processing.
- Use dedicated OpenFOAM or approved external tooling instead.
