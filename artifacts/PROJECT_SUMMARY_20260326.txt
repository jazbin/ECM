TECHNICAL FINDINGS
────────────────────────────────────────────────────────────────────────────

CHALLENGE 1: Heat Source Sign Convention
Problem:    Initial implementation had incorrect sign in fvOptions heat source
Solution:   Corrected to use "-=" operator (OpenFOAM fvMatrix convention)
Result:     Heat generation now correctly integrated; validation passed

CHALLENGE 2: Multi-Region Geometry Capture
Problem:    Coarse mesh (2mm) lost 62% of jellyRoll-shell interface area
Root Cause: snappyHexMesh with insufficient base resolution failed silently
Solution:   Increased base cell size; verified interface areas post-mesh
Result:     Coarse case rejected; base (1mm) and fine (0.5mm) approved

CHALLENGE 3: Mesh-Dependent Transient Behavior
Problem:    Base mesh T_avg = 333.7K vs Fine T_avg = 324.3K at t=300s (9.4K diff)
Root Cause: Fourier number Fo = α·dt/dx² couples spatial and temporal discretisation
            Base: Fo=1.88, Fine: Fo=6.13 (same dt, different dx)
            High Fo causes over-diffusion in implicit Euler
Solution:   Enabled adaptive time-stepping (adjustTimeStep yes, maxDi 50)
Result:     At t=5.9s both meshes converge to ±0.024K (validated mesh independence)

CHALLENGE 4: ECM Call Frequency vs Time Constants
Problem:    Adaptive dt produces dt ≈ 0.006s (fine mesh) >> ECM RC time τ=8-40s
Implication: 50,000+ ECM calls per 300s simulation (overkill for ECM time scale)
Resolution: For OpenFOAM: acceptable (high accuracy, useful for validation)
            For Star-CCM+: recommend ECM subcycling (call every 0.5-1s)

CHALLENGE 5: Alternative Spatial Coupling Strategy
Status:     Distributed 9-zone approach implemented and tested
            Maps cells to 3×3 spatial grid (3 axial × 3 radial partitions)
Finding:    Approach viable but adds complexity without thermal benefit (lumped
            case already spatially uniform in base test conditions)
Assessment: Reserve for future applications with spatial heterogeneity

PERFORMANCE & RUNTIME SUMMARY
────────────────────────────────────────────────────────────────────────────

LUMPED APPROACH (Primary)
Base Mesh (1mm):
  - Cells: 49,784
  - Solver: chtMultiRegionSolidFoam (unsteady implicit)
  - Time: dt adaptive (~0.023s mean)
  - Duration: 75.24s simulation in ~73s execution
  - Speedup: 1.03× real-time (essentially wall-clock speed)

Fine Mesh (0.5mm):
  - Cells: 261,996
  - Solver: chtMultiRegionSolidFoam (unsteady implicit)
  - Time: dt adaptive (~0.006s mean)
  - Duration: 17.58s simulation in ~18s execution
  - Speedup: 0.98× real-time (slightly faster due to rapid convergence)

DISTRIBUTED APPROACH (Alternative)
9-zone Distributed:
  - Cells: 27,144
  - Solver: chtMultiRegionSimpleFoam (steady-state iterative)
  - Time: Pseudo-transient iterations to nominal 100s
  - Duration: 100s nominal in 387s execution (6.4 min wall time)
  - Speedup: 0.26× real-time (3.87× slower than lumped unsteady)

Note: SimpleFoam slower for this application because solid conduction
      has long characteristic time (τ ≈ 2500s), not ideal for pseudo-transient

    - If distributed: can ECM vary across 9 zones or must it be uniform?

ARCHITECTURAL RECOMMENDATIONS FOR STAR-CCM+
────────────────────────────────────────────────────────────────────────────

RECOMMENDED: Quasi-Steady Baseline + ECM Subcycling
- Start with solid + fluid at dt=0.5-1s (thermally-limited, not CFL)
- Call ECM every 1-2s (not every 1ms fluid step)
- Use Jython macro for wrapper (easier than Java, sufficient performance)
- Runtime: ~10-50 hours for 300s discharge (acceptable for iteration)
- Validation: Compare against OpenFOAM baseline on same geometry

ALTERNATIVE (If client requires transient flow effects):
- Fluid CFL-limited: dt=1-10ms
- ECM subcycling: call every 0.5-1s (100-1000 fluid steps per ECM call)
- Wrapper complexity: Higher (manage internal time subcycles)
- Runtime: weeks (millions of solver steps)
- Reserve for final design phase after quasi-steady validation

DISTRIBUTED APPROACH (If spatial heterogeneity critical):
- Implement 9-zone mapping (tested and validated)
- Use transient multi-physics solver (not SimpleFoam)
- Per-zone ECM instances or zone-dependent heat distribution
- Integration effort: +1 week vs baseline
- Validation: Cross-check against lumped baseline
